# meysternlp.ru — сайт психолога Андрея Мейстера

Статический сайт (GitHub Pages → Amvera). Бэкенд приложения «Фреди» — отдельный
репозиторий `Dron939-sketch/Frederick` (FastAPI, https://ffred-ddd989.amvera.io).

## Карта

- `/blog/` — блог (1250+ материалов). Источник истины по рубрикам и статьям —
  `blog/blogmap.json`, полнотекстовый поиск — `blog/search-index.json`.
- `/blog/lektorij/` — Лекторий, «университет жизни». Страницы курсов —
  `/blog/lektorij/<kurs>/`. Лекции — обычные статьи блога `blog/lekciya-*.html`,
  рубрика `lektorij`.
- `/fredi/` — веб-приложение «Фреди». Страница-оболочка: весь текст рисует JS,
  поэтому посадочная для поиска — `/virtual-psychologist/`, а `/fredi/` отдан ей
  через canonical. Не возвращать `/fredi/` в sitemap.
- `vk-drafts/` — черновики постов для ВК (на сайте не публикуются).
- `header.html` / `footer.html` — общие; ряд страниц несёт встроенную копию
  навигации — при изменении меню обновлять все вхождения.

# Как здесь пишут

Главный раздел. Тексты сайта узнаются по голосу — если он теряется, материал
выглядит чужим, даже когда факты верны.

## Голос

**Обращение на «вы», без панибратства и без менторства.** Автор — практик,
который двадцать лет смотрел на это вблизи, а не лектор у доски.

**Начинать с узнавания, а не с определения.** Читатель должен на первых двух
абзацах подумать «это про меня». Определение кладётся потом, на готовое.

> Самое неприятное в обесценивании — что возразить нечего. Вроде ничего
> плохого не сказали, а после разговора ощущение, будто вас стало меньше.

**Конкретика вместо абстракции.** Не «нарушение личных границ», а «мама звонит
в одиннадцать вечера и спрашивает, почему вы не перезвонили днём».

**Короткие фразы там, где мысль поворачивает.** Длинный период — на объяснение,
короткий — на вывод. «Вашими же руками.» «И ведь не ошибётесь.»

**Никакой терапевтической ваты.** Не «важно принять свои чувства», а что именно
сделать, сказать и в каком порядке. Если совет нельзя выполнить сегодня
вечером — это не совет.

**Честность про пределы.** Где данных нет — так и писать. Где нужен врач —
говорить прямо и без смягчений. Раздел «Когда нужен специалист» обязателен
везде, где речь о состоянии, а не о навыке.

**Чего в текстах не бывает:** «дорогие читатели», «в современном мире», «ни для
кого не секрет», «психологи давно доказали», восклицательных знаков пачками,
обещаний «изменить жизнь за 7 дней».

## Анатомия статьи блога

Порядок держится по всему блогу — читатель привыкает и тратит силы на смысл,
а не на форму:

1. **Врез после `<h1>`** — 2–3 предложения: узнавание плюс что будет дальше.
2. **«План статьи»** — 5–6 строк списком, чем статья полезна.
3. **«Содержание»** — `<h2>`, ссылки на якоря разделов.
4. **«Что сделать сразу»** — короткий извлекаемый ответ. Его цитируют машины,
   он же спасает читателя, который дальше не пойдёт.
5. **Основная часть** — по типу серии (см. ниже).
6. **«Когда нужен специалист»** — признаки, при которых текста мало.
7. **«❓ Частые вопросы»** — `<h3>` вопрос, `<p>` ответ. **Обязан быть виден на
   странице**, а не только в JSON-LD: правила Google требуют этого, и именно
   отсюда языковые модели берут цитаты.
8. **«Итоги»**, **«Вопросы для самопроверки»**, **«Литература»**.

## Серии и их разметка

| серия | основная часть | разметка сверх обычной |
|---|---|---|
| «Чем отличается» | таблица различий, определения обоих понятий | `DefinedTermSet`, якоря `#t-<термин>` |
| «Как» | пронумерованные шаги | `HowTo` + `HowToStep`, якоря `#shag-N` |
| «Что делать, если…» | «Что сделать сразу» → шаги → готовые формулировки → чего не делать | `HowTo`, якоря `#shag-N` |
| «Почему» / «Сколько» | прямой ответ в первом абзаце, затем разбор | `Question` с `acceptedAnswer` на `#vopros` |
| лекции Лектория | **строго по `blog/lektorij/METODICHKA.md`** — прочитать целиком до первой лекции | схемы с «голосовыми» `figcaption` |

## VK-посты (`vk-drafts/`)

Формат отдельный, образцы — в самой папке. Объём ~3000 знаков. Шапка файла
фиксирует замысел: заход, механизм, декларация читателя.

Строение: **крючок из жизни читателя** («вспомните человека, с которым сегодня
первым поздоровались») → читатель на своём опыте убеждается, что механизм
реален → **разворот на него самого** → два-три неприятных факта под 🔻 →
**лабораторные доказательства** под 📌 с фамилией и годом → ставки под ⚡ →
**выход** под ✅ с конкретными действиями списком.

Эмодзи — служебные маркеры структуры (👀 🔻 📌 ⚡ ✅), а не украшение.
Жирным — только поворотные утверждения, по одному на блок.

# Чего не делать

Не вкусовщина: каждый пункт — ошибка, которая уже попадала в публикацию.

**Не придумывать источники.** Ни фамилий, ни годов, ни названий работ «по
памяти». Если нет уверенности в написании фамилии или в том, что работа
существует, — описать мысль без ссылки: «в исследованиях привязанности
показано, что…». Выдуманная ссылка на живого учёного — худшее, что может
случиться с текстом.

**Не смешивать алфавиты.** «vыживания», «Аттaчмент», «Сансstein» — латинская
буква внутри русского слова. Глазами ловится плохо, а стоит прямо в `<title>`.

**Не оставлять markdown в HTML.** `**жирный**` и `*курсив*` на опубликованной
странице — это видимые звёздочки. Только `<b>` и `<em>`.

**Кавычки.** Снаружи «ёлочки», внутри „лапки“. Прямые `"` ломают JSON-LD, если
попадают в разметку.

**Не вписывать числа руками.** «1165 статей», «54 курса» разъезжаются с
реальностью в тот же день. Все счётчики пересчитываются из `blog/blogmap.json`
через `tools/sync_counters.py`.

**Не ставить даты вперёд.** `datePublished` в будущем — материал выпадает из
индексации. Дата публикации равна дню, когда файл появился в репозитории.

**Не возвращать `<base href="/">`.** Он ломает каждую ссылку вида `href="#..."`:
по спецификации фрагмент резолвится относительно base, и оглавление уводит на
главную. Один раз это уже случилось на 969 страницах.

**Не размечать то, чего нет на странице.** FAQPage без видимого блока вопросов,
`aggregateRating` без отзывов, `Course` без лекций — основание для санкций.

# Обвязка: что обновить после новой статьи

Материал, которого нет в каталоге, доступен только через поиск — краулер до него
доходит хуже, читатель не доходит вовсе.

1. `blog/blogmap.json` и `blog/search-index.json` — запись о статье.
2. Страница рубрики `blog/rubrika/<key>/` — карточка в свою группу уровня.
3. `sitemap.xml` — адрес с `lastmod`.
4. Хаб `/blog/` — карточка в «Свежее», если материал заметный.
5. `llms.txt` — для серий и справочников.
6. Лекция дополнительно: страница курса плюс ссылка на курс из самой лекции.

Пункт 2 и часть счётчиков делает `tools/sync_counters.py`.

## Инструменты

Перед публикацией и после правок:

```bash
python3 tools/check_site.py    # весь сайт: ссылки, якоря, мета, JSON-LD, sitemap
python3 tools/check_blog.py    # каталоги блога, счётчики рубрик, сироты
```

Оба должны давать **0 ошибок**. Чинящие: `fix_meta.py`, `sync_counters.py`,
`fix_dates.py`, `fix_schema.py`, `fix_catalog_schema.py`, `render_faq.py`,
`fix_nav_fallback.py`, `build_feed.py`. У каждого есть `--dry-run` — сначала
смотреть, что изменится.

`link_lektorij.py` ставит в статьи блога дверь в Лекторий: строку после
«Содержания» и блок перед блоком про Фреди. Курс подбирается по теме, названия
и число лекций читаются со страниц курсов. Прогонять заново после того, как
курс переименован, разделён или в нём изменилось число лекций, — иначе числа
в четырёхстах статьях разъедутся с каталогом.

Рендер проверять локально: `python3 -m http.server 8099` из корня плюс
Playwright (браузер `/opt/pw-browsers/chromium`). Сеть на `meysternlp.ru` и
`ffred-ddd989.amvera.io` из песочницы закрыта — проверять только локально.

должно быть понятно без открывания диффа.
